# Проверка решения для HackAlem AI

Дата: 23 сентября 2026 года.

Исходный ZIP — хорошая основа для повторной закупки по накладной, но не полное решение кейса чат-консультанта. В нём отсутствовали языковая модель, серверный агент и диалог. Надпись «Помощник» выводила заранее заданный текст. README честно описывал ограничения.

Сильные стороны исходника: локальный разбор документов, точный артикул, отклонение неоднозначных совпадений, проверка единиц и суммарных остатков, явное подтверждение. Исходные 9 проверок прошли.

## Что добавлено

| Требование | Новая версия |
|---|---|
| Свободный чат | Настоящий агент OpenAI, контекст сессии, инструменты |
| Наличие и характеристики | Карточки в чате; демо и адаптер настоящего API |
| Сертификат | Ссылки из данных; явно недействительный учебный образец для D-101 |
| Аналоги | Объяснимая демонстрационная матрица; реальные требуют данных EKT |
| Условия покупки | Учебные условия и отдельный снимок официальной страницы EKT |
| Корзина | Серверное подтверждение, актуальные цена/остаток, защита повторов |
| Ссылка на корзину | Общая корзина сессии, /#cart и перезагрузка |
| Вложения | JPEG/PNG/PDF/DOCX/XLSX и текстовые файлы через модель |
| Исходная накладная | Сохранена, подключена к общей корзине |

## Проверки и найденные ошибки

Исходные 9 проверок и 18 новых автоматических сценариев проходят. Проверены: отсутствие изменений без подтверждения, отрицание, повторные запросы, чужая сессия, дубли, дробные количества, изменившиеся цена/остаток, CSRF, Origin/Host, секретные пути и ограничения инструментов модели.

Браузер проверен на десктопе и ширине 390 px: чат, сертификат, аналог, подтверждение/отмена, восстановление корзины, накладная и импорт CSV. Ошибок консоли нет. Исправлен конфликт CSS, скрывавший сообщения помощника на мобильном экране.

Рабочий ключ OpenAI проверен. Живой агент нашёл D-101, подготовил 2 шт без добавления и предложил D-103 как аналог D-102. Успешно прочитал синтетические PNG, JPEG, PDF, Word и Excel. Первый присланный ключ был отклонён; второй работает. Ключи и пароль партнёра не входят в ZIP.

При тестировании модель назвала KZT рублями: валюта явно добавлена в данные инструментов и инструкции, повторная проверка успешна. Модель также дописала единицу при неизвестном поле: неполные/противоречивые карточки теперь получают ответ непосредственно из полей сервера; добавлен регрессионный тест.

API EKT проверен напрямую и через агента. В карточке 515291 название указывает 160 А, свойство — 250 А; единица измерения не подтверждена. Предупреждение отображается, добавление блокируется. Доступность EKT нестабильна: наряду с успешными запросами встречаются тайм-ауты, которые показываются как ошибки.

## Что остаётся перед внедрением

1. API настоящей корзины/заказа и сессия покупателя EKT. Сейчас это корзина прототипа; заказ не создаётся, складской резерв между покупателями отсутствует.
2. Экспертная матрица аналогов, подтверждённые единицы и схема сертификатов. RECOMMEND не считается совместимостью.
3. Полный индекс. По умолчанию поиск ограничен 5 страницами; скрипт полной синхронизации включён, массовая выгрузка не выполнялась.
4. Скорость и надёжность: демо-ответы 2–6 секунд, отдельный успешный EKT-запрос около 15 секунд, есть тайм-ауты. SLA единиц секунд и нагрузка не проверены.
5. Постоянная БД, авторизация, защита публичного сервиса. Сессии локального MVP находятся в памяти. Казахский язык и сложные документы требуют отдельной приёмки.

Итог: исправленная версия подходит для демонстрации MVP. Для промышленного запуска остаются перечисленные интеграционные задачи.
